## Change And Product Impact

Harness `1.2.0` incorrectly required clearance for every planned Agent before the creator could
finish the Run artifacts and before later reviewers had a candidate to inspect. This made a clear
Human task mandate appear to require another approval merely to operationalize that approval.

`1.2.1` keeps the same Spawn Reviewer and Run lifecycle but separates two control boundaries:

- `assignment_preparation` permits read-only analysis and minimum Work/Run/Preflight preparation
  under the exact Human task mandate, without implementation mutation;
- `run_activation` clears only the Agent whose real responsibility begins now. Initial admission
  requires the creator; reviewers remain pending until exact candidate evidence exists.

Security, authority, scope, budget, lease, integrity, stale-binding and independent-review checks
remain fail-closed. A deterministic rebind is accepted only for the exact unchanged assignment
subject; material drift requires a fresh Spawn-Reviewer pass.

## Recalibration From 1.2.0

- Replace only `.agentic-harness/**` through the authenticated upgrade path. Do not rewrite Product
  code, root instructions, Contracts, plans, historical events or provider state.
- Completed/cancelled Runs and valid `1.2.0` Runs remain pinned to their existing rules.
- A non-terminal `1.2.0` Run may remain pinned. To use responsibility-time activation, create an
  authorized current revision or successor under `1.2.1`; do not fabricate prior clearances.
- For new `1.2.1` D1-D3 work, declare the complete Agent plan, activate the creator for initial
  admission, and activate each reviewer only against the exact candidate/evidence it will inspect.
- A direct Human task mandate does not require a duplicate Human approval for analysis or minimum
  control-plane preparation. Missing scope, expanded authority or a distinct Human Gate still stops.

No Product implementation, deployment, provider, Production or customer-data action is authorized.
