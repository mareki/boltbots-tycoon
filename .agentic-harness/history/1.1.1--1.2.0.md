## Change And Product Impact

Every newly activated D1-D3 Agent now requires an exact role brief and independent Spawn Reviewer
clearance before substantive work. The clearance is bound to the brief, routed-source and protected
role digests; stale or incomplete bindings fail closed. D0 remains explicitly proportional and may
record the mechanism as `not_applicable`.

The protected Spawn Reviewer checks that the Agent has the actual objective, authority boundary,
routed sources, outputs, evidence requirements, review questions and stop conditions. It does not
duplicate Product criteria, approve implementation evidence, recursively spawn itself or expand
scope. UI briefs route the existing visual specifications and their required reference and
implementation screenshots.

## Recalibration From 1.1.1

- Completed and cancelled historical Runs remain valid under their pinned Harness version.
- Existing non-terminal Runs may remain pinned to `1.1.1`. Before a new Agent activation under
  `1.2.0`, either create a current Run projection or perform an expressly authorized Contract
  revision with prior/new digests, authority, Git and Run Event evidence.
- Existing Product-owned root `AGENTS.md` remains byte-preserved by compatible upgrade. The newly
  installed protected operating policy still makes Agent Start Control effective.
- Record `required_before_continue` only for a future D1-D3 activation lacking current clearance;
  do not rewrite historical Agent activity or create a duplicate acceptance matrix.
