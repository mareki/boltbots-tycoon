## Correction And Compatibility

Existing Harness duties begin with the Human task, not Run activation. Preparation contributes
actual outcome-based progress; 10-percent reports, 20-percent drift and all other applicable duties
retain their owning triggers. A protected Manifest → Operating Policy bridge reaches supported old
Roots without changing Product files or requiring a special execution prompt.

New ordinary `1.3.1+` Runs use one compact evidence block in the existing Run progress section.
The existing direct checker rejects missing/inconsistent declarations; it does not prove actual
timing, semantic applicability, evidence truth or tool mediation. D0 adds no reviewer. A missed
duty is disclosed and resolved honestly under its existing authority, never backdated as compliant.

## Product Recalibration

- Replace only `.agentic-harness/**`; retain every Product-owned file and historical Run unchanged.
- Existing task authority, Product behavior, Domain Gates and Brownfield activation remain unchanged.
- New tasks use the installed task-entry correction. When continuing the same outcome, carry earlier

  or a concrete future trigger. Do not introduce an automatic Product migration or blanket gate.

This is a patch correction of existing duties, not a new Product requirement or lifecycle.
