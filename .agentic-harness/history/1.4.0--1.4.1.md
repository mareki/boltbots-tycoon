## Change And Compatibility

Domain §12 corrects the unconditional Foundation prerequisite for Product Delivery. A wholly
domain-free Work Package may retain its schema1 Domain Binding with `contexts: []` and the single
nonempty string `not_applicable_reason`, citing the effective scope/context decision through
existing Package sources and exact Run targets. The independent reviewer verifies that the entire
authorized scope qualifies. Unknown impact is not domain freedom; mixed scope binds actual Contexts.

The direct Run checker supports this variant for1.4.1+ Runs; the full Binding checker accepts the
same shape. Existing nonempty Foundation/Legacy Exception bindings remain unchanged. Bootstrap
Domain approval, ordinary authority/status/version checks, design and parent-Slice evidence still
apply. No new Run kind, gate, document, Context, adoption or Product-owned migration is required.
This compatible semantic correction is patch1.4.1; overlay schema1 is retained.

## Focused Product Recalibration

Upgrade replaces protected Core only. Preserve all Product-owned files and completed historical
Runs byte-for-byte. For blocked domain-free work, use its existing approved scope/context sources;
revise only the authorized Package Binding and current Run under the installed version. Resolve its

Unaffected domain-bound work needs no Binding rewrite. Emerging domain impact requires the normal
affected-Context model/exception before that change. Core upgrade does not activate Brownfield
adoption, initialize a Product, or implement its pending Work Package.
