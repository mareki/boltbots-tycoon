## Change And Product Impact

No Contract is immutable. For an Execution Run Contract, an authorized correction or schema
migration increments the revision and records the prior/new SHA-256, reason, Decision/Human
Authority and prior Git commit in a digest-chained Run Contract Revision Event. Other Contract
classes retain their canonical owner-specific revision/version and review mechanism. The new
revision becomes current and Git preserves the old bytes.

Validator admission is now schema/version-aware. A completed or cancelled historical Run is
evaluated under its pinned Contract/Harness rules; fields introduced later are not projected onto
it. A current non-terminal Run must match the installed Harness before activation. Scope Lock,
budgets and fail-closed admission remain mandatory for current Runs.

The former `admission_legacy_run_ids` byte-identity exception is removed. There is no Product- or
Amplorify-specific bypass and no disabled validator family.

## Recalibration From 1.0.13

- Record `no_change` when completed/cancelled historical Runs remain under their pins and every
  current Run already uses a complete current Contract.
- Record `required_before_continue` for an old non-terminal Contract that must enter or re-enter
  `active`: migrate it through the released Contract-revision mechanism before current admission.
- A terminal historical Contract MAY be migrated for schema/audit consistency, but the migration
  keeps its terminal state and creates no execution authority.
- Never bulk-edit Product Contracts during Core replacement. Every Product-owned revision needs its
  named Decision/Human Authority and Git/Event evidence.

No Product code, deployment, provider, AWS, Production or customer-data action is authorized.
