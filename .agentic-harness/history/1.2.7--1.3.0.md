## Change And Product Impact

New Greenfield initialization establishes a reviewed Domain Foundation before the remaining Product
initialization. It defines Bounded Contexts, their relationships and contracts, use cases,
invariants, ownership, and intended module boundaries. Implementation-ready Contexts map to
technical modules; each module uses a pragmatic hexagonal boundary with domain/application logic
independent from delivery and infrastructure adapters.

Brownfield Products may adopt the Harness separately without a big-bang rewrite. The adoption
entrypoint stages only `.agentic-harness/**` as `inactive_staged` and leaves every Product-owned
file unchanged. Later Human-authorized integration classifies Context coverage incrementally.

## Recalibration From 1.2.7

- Replace only `.agentic-harness/**` through the authenticated upgrade path.
- Do not migrate or rewrite historical Runs; their pinned meaning remains valid.
- Core upgrade alone does not activate Brownfield adoption and creates no Product-owned domain,
  routing, lifecycle, plan, module, port, or adapter artifact.
- For a Product without an installed Harness, use the separate safe Brownfield adoption path when
  explicitly authorized.
- For new `1.3.0+` Product Delivery Runs, bind each changed Context to the exact effective Domain
  Foundation revision or an approved context-specific legacy exception.

No Product-owned artifact or legacy source structure requires automatic migration.
